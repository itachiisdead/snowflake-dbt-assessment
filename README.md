# snowflake-dbt-assessment
DBT Project Customer Revenue Analysis
This is a simple dbt project I built on top of Snowflake’s TPCH sample dataset, to show how to organize raw data into models and then build a model that calculates customer revenue.

How to Run This Project:

1. Set Up Your Snowflake Connection
I've set up a connection in dbt Cloud, but you need to define your connection details:

Environment Variables: You must set the following variables in your environment:
SNOWFLAKE_ACCOUNT
SNOWFLAKE_USER
SNOWFLAKE_PASSWORD
Database Details: The models will expect to find data in these specific locations:
Database: DEMO_DB
Schema: DBT_SCHEMA
Warehouse: DEV_WH

2. Project Structure
Make sure you clone this repository and place the files in this exact structure:
├── dbt_project.yml
├── models/
│   ├── stg_orders.sql
│   ├── customer_revenue.sql
│   └── schema.yml
└── README.md

what each model does:
stg_orders.sql (Staging/Cleaning): Takes the raw TPC-H order data and standardizes it.	Selects and renames core fields: order_id, customer_id, order_date, and total_price.
customer_revenue.sql (Aggregate): Calculates the total revenue generated by each customer.	Groups the cleaned order data by customer and sums the total_price.

3. Run the Models
Once everything is set, use these commands in your terminal or dbt Cloud IDE:

dbt run: Builds all the models (tables/views) in your Snowflake database.
dbt test: Checks data quality using the defined tests (like Not Null, Unique, etc.).
dbt docs generate: Creates the static documentation website.
dbt docs serve:	Opens the local documentation website in your browser.
 
Data Quality & Documentation:
Data Tests:
Not Null: Checks that columns are always filled.
Unique: Ensures primary keys (like order_id and customer_id) are not duplicate.
Relationships: Confirms that every customer_id in the orders data actually exists in the source customer table.

Documentation
Every model and column has a clear description defined in schema.yml.
You can view the full documentation by running dbt docs generate and opening the documentation tab in dbt Cloud.

Assumptions:
The total_price field from the TPC-H orders table accurately represents the order total/revenue.
We can use the customer_id field as the single, main key for joining orders and customer records.
