# Snowflake DBT Assessment
DBT Project: Customer Revenue Analysis
Analyzing customer revenue using Snowflake’s TPCH sample dataset. I transformed raw data into organized models, culminating in a model that calculates customer revenue.

## How to Run This Project
1. Set Up Your Snowflake Connection
I've tried both using the DBT clould IDE, and also the Local environment DBT (CLI). 

### Environment Variables: 
Make sure to set the following variables in your environment:
- SNOWFLAKE_ACCOUNT
- SNOWFLAKE_USER
- SNOWFLAKE_PASSWORD

### Database Details: 
The models expect data to be found in these specific locations:
- Database: DEMO_DB
- Schema: DBT_SCHEMA
- Warehouse: DEV_WH

2. Project Structure
Clone this repository and ensure the files are organized in the following structure:

- dbt_project.yml
- models{stg_orders.sql, customer_revenue.sql, schema.yml }
- README.md
  
### Model Descriptions
- stg_orders.sql (Staging/Cleaning): This model processes the raw TPC-H order data, standardizing it by selecting and renaming core fields: order_id, customer_id, order_date, and total_price.
- customer_revenue.sql (Aggregate): This model calculates the total revenue generated by each customer by grouping the cleaned order data and summing the total_price.

### 3. Run the Models
using these commands in your terminal or DBT Cloud IDE:

- dbt run: Builds all the models (tables/views) in your Snowflake database.
- dbt test: Checks data quality using the defined tests (e.g., Not Null, Unique).
- dbt docs generate: Creates the static documentation website.
- dbt docs serve: Opens the local documentation website in your browser.

### Data Quality & Documentation
Data Tests:
- Not Null: Ensures that important columns are always filled.
- Unique: Validates that primary keys (like order_id and customer_id) are not duplicated.
- Relationships: Confirms that every customer_id in the orders data exists in the source customer table.

###  Documentation
- Every model and column has a clear description defined in schema.yml.
- You can view the full documentation by running dbt docs generate and opening the documentation tab in dbt Cloud.

### Assumptions:
- The total_price field from the TPC-H orders table accurately represents the order total/revenue.
- We can use the customer_id field as the single, main key for joining orders and customer records.
